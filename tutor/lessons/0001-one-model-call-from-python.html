The big picture: one request, one reply O1 3 min

Calling a model from code is an ordinary function call over the network. Your program sends one request, and the model sends back one reply. With Anthropic's Messages API the request carries three things you always pass (Messages API reference):

  • model: which model answers, as an id string such as "claude-haiku-5-5", the cheapest in the current lineup and fine for practice (Models overview);
  • max_tokens: the most the reply may contain, counted in tokens (word pieces);
  • messages: the conversation so far, as a list of dicts, each with a "role" ("user" or "assistant") and a "content".

The reply is an object with the model's answer in content, plus why it stopped (stop_reason) and how many tokens went in and out (usage) (Using the Messages API, “Basic request and response”).

Think of it like a parts counter where the clerk keeps no records. Every time you walk up, you hand over the full work order, and whatever isn't on that paper the clerk doesn't know. The rest of this lesson is about filling in that work order correctly.

Make the call O1 3 min + 10 min demo

The official quickstart does three things: it installs the anthropic package, it puts your key in the ANTHROPIC_API_KEY environment variable, which the SDK reads by itself, and it calls client.messages.create(...) (Get started with Claude, “Before you begin” and “Call the API”). Because the key lives in your shell and not in the script, you can share or commit the code without leaking it.

Demo: one call, then a conversation O1 10 min

Build it: one call, then a conversation

Make a folder, say first-call/, and work in it. You need only Python 3, with no key and no network: fake_claude.py stands in for the real API with the exact same call shape, so everything you write here works unchanged against the real thing in step 7.

  1. Save the stand-in. Copy this into fake_claude.py. You don't have to study it, but notice the one comment that matters: it only knows what is in the messages list you hand it, which is exactly how the real API behaves.

    Show fake_claude.py (25 lines)
    # fake_claude.py - a stand-in for client.messages.create; no key, no network.
from types import SimpleNamespace as NS

LONG = ("A torque converter is a fluid coupling between the engine and the "
        "automatic transmission. The engine spins an impeller, which flings "
        "transmission fluid at a turbine connected to the gearbox, so the car "
        "can sit still in gear while the engine idles.")
SHORT = "It links engine to gearbox through spinning fluid, so the car can idle in gear."

def create(model, max_tokens, messages):
    last = messages[-1]["content"].lower()   # it sees ONLY this list
    if "torque converter" in last:
        text = LONG
    elif "shorter" in last:
        seen = any(m["role"] == "assistant" for m in messages)
        text = SHORT if seen else "Shorter than what? I see no earlier message."
    else:
        text = "This stand-in only knows about torque converters."
    words, stop = text.split(), "end_turn"
    if len(words) > max_tokens:               # pretend 1 word = 1 token
        words, stop = words[:max_tokens], "max_tokens"
    used = sum(len(m["content"].split()) for m in messages)
    return NS(role="assistant", stop_reason=stop,
              content=[NS(type="text", text=" ".join(words))],
              usage=NS(input_tokens=used, output_tokens=len(words)))

  2. Make one call. Save this as call.py and run python3 call.py. You pass the three things every call needs: a model, a ceiling on reply length, and the conversation as a list of role/content dicts.

    import fake_claude as claude   # step 7 swaps in the real client

messages = [{"role": "user", "content": "Explain how a torque converter works"}]
reply = claude.create(model="claude-haiku-5-5", max_tokens=1000, messages=messages)

for block in reply.content:
    if block.type == "text":
        print(block.text)

    You should see

    A torque converter is a fluid coupling between the engine and the automatic transmission. The engine spins an impeller, which flings transmission fluid at a turbine connected to the gearbox, so the car can sit still in gear while the engine idles.

  3. Look inside the reply. Add these two lines to the end and run again. The reply's content is a list of blocks, not a string, which is why step 2 loops and keeps the "text" blocks.

    print(reply.content)
print(reply.stop_reason, reply.usage.output_tokens)

    You should see

    [namespace(type='text', text='A torque converter is a fluid coupling ... while the engine idles.')]
end_turn 42

    The real SDK prints the block as TextBlock(..., type='text') instead of namespace(...), and counts real tokens rather than words, but the shape is the same.

  4. Follow up the wrong way. Add this and run. It sends only the new question, the way it feels like a chat should work.

    followup = [{"role": "user", "content": "Make it shorter"}]
reply2 = claude.create(model="claude-haiku-5-5", max_tokens=1000, messages=followup)
print(reply2.content[0].text)

    You should see

    Shorter than what? I see no earlier message.

    The call before this one is gone. Nothing linked the two calls, because they are two separate function calls.

  5. Follow up the right way. Add the model's earlier reply to your list as an "assistant" turn, then the new "user" turn, and send the whole list.

    messages.append({"role": "assistant", "content": reply.content[0].text})
messages.append({"role": "user", "content": "Make it shorter"})
reply3 = claude.create(model="claude-haiku-5-5", max_tokens=1000, messages=messages)
print(len(messages), "|", reply3.content[0].text)

    You should see

    3 | It links engine to gearbox through spinning fluid, so the car can idle in gear.

    Three dicts went in: user, assistant, user. Your program wrote the assistant turn, copying the earlier reply into it.

The wording will differ on every run.

In step 3 you saw the reply's content printed as a list. The quickstart's own code loops over it the same way you did, keeping blocks whose type is "text" (Get started with Claude, “Call the API”). A plain question gets one text block back. Later, when you add tools, a reply can hold a tool request as a block of its own, which is why it's a list and why you check type.

A common mix-up

“reply.content is the answer.” It's tempting because in your request, "content" was a plain string. In the reply it's a list of blocks, so print(reply.content) shows a list, and string methods on it fail. Pull the text out: reply.content[0].text for a quick look, or the loop for real code.

The API remembers nothing O1 4 min

Anthropic's docs put it in one line: “The Messages API is stateless, which means that you always send the full conversational history to the API” (Using the Messages API, “Multiple conversational turns”). Stateless means each call stands alone. The server doesn't hold your conversation between calls, so the only memory the model has is the messages list in the request in front of it. That's what step 4 of the demo showed: “Make it shorter” on its own got “Shorter than what?”

So to continue a conversation, your program does the bookkeeping. After each reply, it appends that reply as an "assistant" turn, appends the next "user" turn, and sends the whole list. The models are trained on turns that alternate user, assistant, user (Messages API reference), so the list grows by two per exchange.

A common mix-up

“The API remembers the earlier call, because it's the same key or the same program.” This was your pick on the diagnostic quiz, and it's tempting because chat apps feel continuous. That continuity is the app quietly resending the history for you. The key only says who's paying. Leave the history out and the model starts from zero, as step 4 showed.

A second mix-up

“Only the model can write "assistant" turns.” The name makes it sound like the model's territory, but the model never touches your list. Your program writes its earlier replies in as "assistant" dicts, as you did in step 5. The docs' own example is a list your code wrote: user “Hello, Claude”, assistant “Hello!”, then user again (Using the Messages API, “Multiple conversational turns”).

max_tokens is a ceiling, not a target O1 2 min

The reference defines max_tokens as “the maximum number of tokens to generate before stopping”, and adds that it “only specifies the absolute maximum” (Messages API reference). It works like a rev limiter: it doesn't set how fast the engine runs, it only cuts in at the top. A reply that finishes on its own comes back with stop_reason "end_turn". One that hits the ceiling is cut off mid-thought and says "max_tokens" (Using the Messages API), which is what step 6 showed.

A common mix-up

“Set max_tokens to 50 to get a short answer.” It sounds like a length setting, but the model doesn't aim for it. You get a normal-length answer chopped off at 50 tokens. To get a short answer, ask for one in the message (“in one sentence”), and keep max_tokens roomy.

Worked example and practice O1 2 min

Worked example

Turn the demo's follow-up into a reusable helper, ask(messages, question), that keeps the history for you.

  1. Append the question as a user turn, because the model only sees what's in the list.
  2. Call create with the whole list, because the API is stateless.
  3. Take the text from the reply's text blocks, because content is a list of blocks.
  4. Append that text as an assistant turn, so the next call has it, and return it.
def ask(messages, question):
    messages.append({"role": "user", "content": question})
    reply = claude.create(model="claude-haiku-5-5", max_tokens=1000, messages=messages)
    text = "".join(b.text for b in reply.content if b.type == "text")
    messages.append({"role": "assistant", "content": text})
    return text
Your turn

Using ask, write the three lines that start an empty conversation, ask “Explain how a torque converter works”, then ask “Make it shorter” and print the answer. Run it against fake_claude. Before you run it, predict how long messages is afterwards. The first line is chat = [].

Show a solution 
chat = []
ask(chat, "Explain how a torque converter works")
print(ask(chat, "Make it shorter"))   # the short answer
print(len(chat))                      # 4: user, assistant, user, assistant

It prints the short answer, because the second call carried the first exchange. The list ends at 4, because ask also stored the last reply, ready for a third question.

Summary O1 1 min

  • One call is one request and one reply: client.messages.create(model=..., max_tokens=..., messages=[...]), with the key read from ANTHROPIC_API_KEY, never written in the code.
  • The reply's content is a list of blocks; take .text from the "text" ones.
  • The API is stateless: your program appends each reply as an "assistant" turn and resends the whole list every call.
  • max_tokens is a ceiling; stop_reason "max_tokens" means the reply was cut off.
