Warm-up O1 1 min

Recall

You traced "Is the laser cutter free on Friday?" through the agent loop. When the calendar result comes back, how many separate model calls has the request used by the time the final answer is written?

Check your answer

Two: one that asks for the calendar tool, and one that reads the result and writes the answer. Each step of the loop is its own model call, and the program, not the model, ran the tool. Today's question is what the second call is given to read.

The context window O3 2.5 min

The context window is all the text the model can look at when it produces a reply, including the reply it is writing; it works as the model's working memory (Context windows). It is measured in tokens, the chunks of text a model reads and writes.

For the makerspace assistant, the window holds four things (Context windows):

  • the system prompt (its role and rules),
  • the definitions of its tools,
  • the messages so far, the student's and the model's,
  • the tool results, such as calendar entries or a manual page.

The crucial point is that the model keeps nothing between calls. Each call, the program sends the history again as input, so the model only "remembers" what is resent (Context windows). Think of a car dashboard: it shows only what the sensors report right now, and anything not wired to it is invisible to the driver.

That has a cost consequence: because the history is resent, a long tool result counts as input again on every later call. Prompt caching can lower the price of resent tokens, but they still fill the window (Context windows). Try it.

Demo (O3, about 3 min): a booking request, call by call

  1. Predict: will the calendar result still count at call 3? Step to find out.
  2. Untick Resend earlier steps, then go to call 2. What can the model see?
A common mix-up

"The model remembers the earlier steps." It is tempting because a chat feels continuous. In the demo, with resending off, the model at call 2 sees the calendar result but not the student's request. Without the resend, it has nothing to go on.

Check yourself

The assistant's manual-search tool returns a 4,000-token page at step 2 of a 6-step request. What happens to that page's cost?

Show the answer

The third option: the history is resent each call, so the page is input again on steps 3 to 6.

Between steps and between sessions O3 1.5 min

Within one session, the earlier turns are preserved in full and resent each call (Context windows). Between sessions, nothing carries over: the window holds only what the program sends, so a new session starts without the old history (Context windows) unless notes saved outside it get loaded in (Effective context engineering). So "Riley completed laser-cutter training" is forgotten on the next visit unless the program stores it and puts it back.

A long session has a second problem: the window fills. One fix is compaction: when the context nears its limit, the agent summarizes it and starts a fresh window from that summary (Effective context engineering).

Check yourself

A student books a printer on Monday, closes the chat, and returns on Wednesday. Without any saved data, what does the assistant's window contain at the start?

Show the answer

The third option: only the fixed parts and the new message, because nothing was saved outside the window.

Retrieval and notes as memory O3 1.5 min

Two tools get information into the window without stuffing everything in at once, and both come from Effective context engineering.

  • Retrieval (just in time): the agent keeps only references, such as manual file names, and uses a tool to load the one page it needs when it needs it.
  • Notes: the agent writes what matters, like a student's training status, to storage outside the window, and reads it back later.

Load only what a question needs: a 300-page manual in every call would be billed again on every step.

Check yourself

The assistant must know a student's laser-cutter certification date next month. Which fits best?

Show the answer

The first option: a note saved outside the window and reloaded next visit.

Worked example and practice O3 2 min

Worked example

Decide where each item for the assistant lives: in context, saved, or retrieved. Item: "the laser cutter's kerf-width table (how much material the beam removes), page 41 of its manual."

  1. Ask whether every step needs it. No, only a cutting question does, so it should not sit in the window all session.
  2. Ask whether it must outlive the session. No, the manual is fixed and already stored.
  3. So it is retrieved: keep the file name in context, and a tool loads page 41 when a question needs it.
Your turn

Classify two items. First step given: ask whether every step needs it. (a) The assistant's rule "never book a machine without a training record." (b) "Student 4417 finished 3D-printer training on March 3."

Show a solution

(a) Every step needs it, so it lives in the system prompt, in context on every call. (b) No step needs it all the time, but it must outlive the session, so it is saved as a note and loaded when that student returns.

Summary O3 0.5 min

  • The context window is the model's working memory: prompt, tool definitions, messages and tool results.
  • The model keeps nothing between calls; history is resent, so long results cost again each step.
  • New sessions start empty; compaction, retrieval and notes are how information is kept or brought in.

Say it in your own words: without looking, explain to a teammate why the assistant needs notes and retrieval in addition to a big window.
