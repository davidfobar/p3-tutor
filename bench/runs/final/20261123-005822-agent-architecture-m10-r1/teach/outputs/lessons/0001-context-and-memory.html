Context and memory: what the assistant sees, keeps and looks up

Warm-up O2 1 min

Recall

In the agent loop, a student asks "Is the laser cutter free on Friday?" The model asks for the calendar tool, and the result comes back. What does the model have to be given on its second call, and why?

Check your answer

Every step is a separate model call, so the model remembers nothing by itself. It must be given the question, its own tool request and the result again: the story so far. Today is about what that story is made of, and what happens when it gets long (Context windows).

The context window O3 2 min

The context window is all the text the model can look at when it writes its next token, and that includes the reply it is writing (Context windows). Think of it as the model's workbench: it can only use what is on the bench right now. The window holds the system prompt, the conversation, the tool results and the tool definitions, all sharing one limit (Context windows).

Picture a car's fuel tank in reverse: the free room is what is left, and a fuller window is not a better one. Accuracy and recall can degrade as the window grows, which Anthropic calls context rot, so the goal is the smallest set of text that gets the job done (Effective context engineering). How the size of the window affects cost is the next lesson's topic.

A common mix-up

"The model remembers my earlier chat." It is tempting because chatbots feel continuous. But the model sees only what is in its window; the app resends earlier turns each time (Context windows). A new session starts with an empty window and no trace of yesterday.

Check yourself

A student's session ends. Tomorrow they open a new session and ask "Am I cleared for the laser?" With nothing else built, what does the model see?

Show the answer

The last option. The window starts with the setup text and the new question only; anything about yesterday has to be put there by your program.

Kept between steps O3 1.5 min

Within one session, earlier turns are kept by being sent again as input on every call (Context windows). Each loop step therefore adds a request and a result to the window, and the window only grows. Two moves make room (Effective context engineering):

  • Clear old tool results. The lightest thing to drop: a manual page read three steps ago has usually done its job.
  • Compaction. Summarize a near-full conversation and restart with the summary. Details left out of the summary are gone.

Try both below. The window has ten slots, an example size only.

Kept between sessions: notes O3 1.5 min

Since every session starts with an empty window, anything the assistant should know tomorrow must be saved outside it. The pattern is structured note-taking: the agent writes notes to storage outside the window and reads them back in later (Effective context engineering). It is like the service logbook in a car's glovebox: the mechanic does not remember your car, the book does.

A common mix-up

"A bigger window replaces memory." It is tempting because more room feels like more remembering. But a window is emptied when the session ends, however large it is, and a fuller one can recall worse (Effective context engineering). Notes outlast any window.

Retrieval: finding the right manual page O3 1.5 min

The manuals are far too long to put in the window. Retrieval means fetching only the piece needed, when it is needed. One approach keeps lightweight identifiers, such as file paths, and loads the content at run time with a tool (Effective context engineering). It works like a car's service manual: you read the index, then turn to the brake pads page, not the whole book.

The trade-off: loading at run time is slower than a precomputed lookup, but it keeps the window small (Effective context engineering).

Worked example and practice O3 1.5 min

Worked example

A student says: "I finished the laser safety class. Book me Friday at 2." Where should each piece go?

  1. "Finished the safety class" is a fact for tomorrow. Save it as a note, because the next session starts empty.
  2. The booking request is needed now. Keep it in the window for this session.
  3. The laser manual's safety page is only needed once. Retrieve it by path when asked, and clear it afterward.
Your turn

Next the student asks, "What speed should I use for 3 mm acrylic?" The assistant has three things: the student's name and training status, the calendar answer from five steps ago, and the manual's cutting-settings page. Sort them into keep, clear, note and retrieve. First step: the status is already a note, so the assistant reads it at the start.

Show a solution

The status is read from the notes into the window at the start. The old calendar answer is a tool result that has done its job, so clear it. The cutting-settings page is retrieved by its path from the manual index, used for the answer, then cleared. Nothing new needs a note unless the student's status changes.

Summary O3 0.5 min

  • The window is working memory: everything the model sees, shared by instructions, tools, history and results.
  • Between steps, history is resent; clear old results or compact when it fills.
  • Between sessions, only notes saved outside the window survive.
  • For long manuals, keep paths and retrieve the page when needed.

Say it in your own words: explain to a teammate why the assistant cannot just remember a student, and where you would put that student's training status.
