The context window O3 2 min

A model knows only its training plus the text it is given. The context is the set of tokens included when sampling from the model (Anthropic, context engineering). The context window is all the text the model can reference when generating a response, including the response itself (Claude docs, Context windows). A token is the chunk of text the model reads and writes, roughly a short word or word piece, and tokens are what the window is measured in and what you are billed for.

Think of the window as the workbench in a garage. The mechanic can only work with what is on the bench, and the bench has a fixed size. The docs list what sits on it: the system prompt, every message including tool results, the tool definitions, and the output for the turn.

A common mix-up

"A bigger window means I can paste in the whole manual." It fits, but the docs warn that more context is not automatically better: as tokens grow, recall accuracy degrades, an effect called context rot (Claude docs). Anthropic's advice is the smallest set of high-signal tokens (context engineering). If the input is too long, the API returns an error.

Between steps and between sessions O3 2 min

Each loop step is its own model call. Each turn's input holds the whole conversation history plus the new message, and the output becomes part of the next turn's input (Claude docs). So the program sends the history again every call, and the context grows. The model is not carrying anything inside itself: like a car's trip computer, the numbers are only there because something keeps feeding them in.

Between sessions, the context is simply not there. Anything that should survive has to be written outside the context by your program and loaded back later. That is the whole difference between working memory (the context) and saved memory (a file or database).

    Retrieval and notes O3 3 min

    Two techniques keep the bench tidy. Retrieval brings only the relevant part of a large source into the context. Anthropic describes two styles: loading data up front with embedding-based retrieval before the model runs, and "just in time", where the agent keeps lightweight pointers such as file paths and loads content with tools when needed. Just-in-time is slower than pre-computed retrieval, a hybrid is often used, and the advice is to do the simplest thing that works (context engineering, retrieval section). Either way, the program or a tool chooses what enters the context; the model sees only what is loaded.

    Structured notes are the second: the agent regularly writes notes to storage outside the context window, and they are pulled back into the context later (same post, "Structured note-taking"). Claude Code's to-do list is one example. Notes cover facts across sessions, such as training status.

    When a long session nears the limit, compaction summarizes the conversation and starts a new context with that summary (same post, "Compaction").

    Worked example

    Decide where "Riley finished laser training" lives.

    1. It must outlive the session, so it cannot live only in the context.
    2. Write it to a database or notes file when training is completed.
    3. At the start of each visit, the program loads it into the context.

    Summary O3 1 min

    • Context is everything sent to the model in a call, and the window is its limit.
    • Each loop step resends and grows the history; a new session starts empty.
    • Notes in storage carry facts between sessions; retrieval loads only the relevant page.
