Context and memory in an agent

From lesson 1. Objective O3.

Where information lives

PlaceLastsUse for
Context windowOne sessionWhat the model sees now: system prompt, tool definitions, messages, tool results
Notes / memory filesAcross sessionsShort facts the agent learned; the program loads them at session start
RetrievalPermanent storeLong documents; only the best chunks enter the window
System of recordPermanentFacts that must be exact (training status, bookings), read by a tool

Rules

  • The model keeps nothing between calls; the program resends the whole history.
  • Input cost of a call = everything in the window so far. Total = sum over calls.
  • More context is not better: context rot. Keep tool results small; clear, compact or hand to a sub-agent when long.
  • New session = empty window. Save notes before results are cleared or the session ends.
  • Retrieval: chunk, embed, search, add top chunks. Add keyword search (BM25) for exact codes; give chunks their context.
  • Under about 200,000 tokens (about 500 pages) you may skip retrieval; weigh cost and rot first.
