Context and memory in an agent

The context window O3 2 min

Think of a mechanic at a workbench. Only what is on the bench is in front of them. The model works the same way: its context is the set of tokens it is given when it writes (Anthropic, context engineering). A token is a chunk of text, roughly a short word or part of one. The context window is all the text the model can use for one response, including the response itself, and the docs call it a "working memory" (Claude docs, context windows).

Everything counts toward it: the system prompt, tool descriptions, every message, every tool result, and the answer being written (same page). Tokens are also what you pay for, so a bigger input is a bigger bill.

Check yourself

Your assistant's tool descriptions take 2,000 tokens. Do they count toward the context window?

Show the answer

Yes. The window holds the system prompt, tool descriptions, messages and tool results, so the descriptions are paid for on every call.

What the model sees on each step O3 3 min

Between steps, the model keeps nothing. Each call's input holds all previous history plus the new message, and its output becomes part of the next input (Claude docs). So your program rebuilds the whole input every step, and an agent in a loop "generates more and more data" that must keep being refined (Anthropic). Think of a fuel gauge reading the whole tank each time: nothing is "remembered", it is all re-measured.

What to notice

Each call re-reads everything from the start: the instructions, the tool descriptions, the question, and every earlier result. Call 2 costs more than call 1 even though the student said nothing new. Switch the manual setting, press Start over, and run again to compare the totals. Nothing here was remembered by the model; the program rebuilt the input each time.

You saw call 2 read more than call 1 with no new question. That is why long agent runs get expensive, and why the next point matters.

A common mix-up

"The model remembers the earlier steps." It feels that way because chatbots are continuous. But the model only sees what your program sends. Drop step 2's result from the input and, for the model, it never happened.

Bigger is not better

You might think a huge window solves everything. As token count grows, accuracy and recall degrade, which the docs call context rot, and "more context isn't automatically better" (Claude docs). Anthropic's guideline is the smallest set of high-signal tokens that gets the job done (Anthropic). When a run nears the limit, compaction summarizes the conversation and restarts a fresh window with the summary; clearing old tool results is the lightest version (same Anthropic post).

Between sessions: notes O3 2 min

When the chat ends, the window is gone. Nothing carries over to Tuesday unless your program saved it. The fix is notes: the agent writes facts to storage outside the window, such as a file or a database row, and they are "pulled back into the context window at later times" (Anthropic, structured note-taking). In Anthropic's example, Claude playing Pokémon kept tallies like how many levels a creature had gained and read them after a reset (same section).

A car works the same way. The dashboard shows what is happening now, and the service logbook in the glovebox holds history. Memory across visits is the logbook, and your program has to write it and open it.

A common mix-up

"The assistant will just know a student passed training." Nothing in the model learns from a chat. Without a saved record, Tuesday's call starts blank.

Long manuals: retrieval O3 2 min

Notes are for facts you save. Retrieval fetches the right part of a big source into the window when it is needed, like opening one page of the repair manual instead of carrying the shelf. Two styles exist: searching up front before the model runs, or "just in time", where the agent keeps light pointers such as file paths or queries and loads content on demand; many systems mix both (Anthropic, context retrieval). Anthropic also notes that one call with retrieval is often enough, before reaching for a full agent (Building effective agents).

Worked example

A student asks, "What speed should I run the lathe for aluminum?" The manuals total 3,000,000 tokens.

  1. Pasting everything is impossible for most windows and costly in any case, so search instead.
  2. The program (or a search tool the model calls) finds the 2 pages on lathe speeds, about 1,600 tokens.
  3. Only those pages join the context with the question; the model answers from them.

Show a solution

Notes: a saved record of the student's training status, loaded at the start of the session. Retrieval is not needed for this question, because the answer is a short saved fact, not a manual page. Only that note enters the context.

A common mix-up

"Put the whole manual in context so nothing is missed." It is simple, which is why it tempts. But you pay for it every step and recall suffers, as you saw in the demo.

Summary O3 1 min

  • The context window is everything the model reads for one call, and you pay per token.
  • Between steps, your program re-sends the growing history; the model remembers nothing itself.
  • More context can mean worse recall, so keep it small and high-signal.
  • Between sessions, only saved notes survive; retrieval brings in just the page needed.
