Context, memory and retrieval

From Lesson 1. Sources: Effective context engineering, Context windows.

WhereWhat lives thereLastsCost
ContextSystem prompt, tool definitions, messages, tool results, model outputOne session; resent every callBilled as input on every call
MemoryShort curated notes (training status, bookings, open issues)Between sessions, in storage the program controlsOnly what you load
RetrievalLong manuals, split into chunks and indexedPermanent, outside the contextOnly the best few chunks enter the context
  • The model keeps nothing between calls; the program resends the history.
  • A bigger window is not better: recall falls as it fills (context rot).
  • Trim with clearing (old tool results) or compaction (a summary).
  • Memory never changes the model; it is notes loaded into a new context.
  • Use exact-word search (BM25) and meaning search (embeddings) together.
  • Sort an item: needed on every call? Context. Needed next session? Memory. Big text, small part per question? Retrieve.
